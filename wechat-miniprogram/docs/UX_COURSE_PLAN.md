# 心智探索局 · 用户交互与「课程」信息架构规划

> **日期**：2026-11-18
> **状态**：首期已实施（首页与列表减负、3 条课程试点）；已补充路线目标、实践提示与可选回顾；待微信开发者工具走查
> **基线**：27 测评 / 24 方法 / 36 训练 / 16 页面 / 纯本地 Storage / 无后端
> **配套文档**：[`ARCHITECTURE.md`](ARCHITECTURE.md)（架构）、[`CODE_REVIEW.md`](CODE_REVIEW.md)（缺陷清单）

---

## 1. 问题诊断

**结论：问题不在于内容多，而在于用户一进来就要自己做「选题」决策。**

87 个内容项（27 测评 + 24 方法 + 36 训练）全部平铺成目录；首页又同时给出统计数字、全局搜索、10 张热门卡、6 张最近卡——用户看到的是**「库」，不是「下一步该做什么」**。

| 位置 | 现状 | 问题 |
| --- | --- | --- |
| 首页 | 数字统计 + 全局搜索 + 10 热门 + 6 最近 | 首屏没有唯一主行动；10 张卡等于"再选一次" |
| 5 个 Tab | 首页/测评/方法/训练/我的 | 三个平行大目录，用户不知道先点哪个 |
| 列表页 | 27 / 24 / 36 项默认全量展开 | 一次扫 20+ 张卡，没有"新人先看这几个" |
| 详情页 | 简介→详解→来源→统计→提示→关联→按钮 | 决策信息（适不适合我、要多久）被资料信息淹没 |
| 新老用户 | 同一套首页 | 新用户没有引导，老用户没有"继续" |

四个结构性缺失：**无个性化**（所有人同一面墙）、**无引导路径**（没有下一步/进度/完成感）、**无叙事**（按学科分类组织，而非按用户目标组织）、**首屏过载**（统计数字强化"目录感"）。

---

## 2. 总体设计：三层信息架构

```
目标（用户自述，1 个问题）
   └─ 课程（3~7 步路线，每步 = 一个现有内容 + 一句"为什么"）
        └─ 全库（现有三个库页，降级为"浏览全部"二级入口）
```

**设计原则**

1. 复用现有量表、方法与训练，不复制或改写其原文；允许补充简短的课程目标、实践提示和本地回顾，帮助用户把已有内容连成学习路径。
2. 从"内容库"转向"学习路径"：首页主入口从"87 个条目"变成"课程 + 继续上次"。
3. 守住离线优先：无后端、无强制登录、无推送。所有个性化用**规则式**（用户自述目标为主信号），不做 ML。
4. 不做连续打卡惩罚——没有后端和订阅消息，做不到推送，唯一召回手段是"上次停在哪"。
5. 三个库页保留，降级为"浏览全部"，老用户习惯不受损。
6. 推荐必须可解释、可撤销：展示推荐依据，用户能改目标、跳过课程或回到完整目录。
7. 心理健康相关内容只作为自我探索与一般练习，不以课程或量表结果替代诊断、治疗或危机干预。

## 3. 用户分群 × 课程目录（候选 7 + 1）

### 3.1 首启目标 → 课程映射

| 首启选项（"你现在最想解决什么？"） | 对应课程 |
| --- | --- |
| 🧭 想更了解自己 | ① 5 分钟认识自己 |
| 😮‍💨 想练习调节情绪或压力 | ④ 7 天情绪调节练习（职场人可选 ⑧） |
| 🎯 专注力差、总拖延 | ③ 7 天专注力 |
| 🧑‍🎓 专业/职业方向迷茫 | ② 职业定位 3 步 |
| 😴 睡不好 | ⑤ 睡眠与放松 7 天 |
| 🫂 人际关系/沟通 | ⑥ 关系沟通练习 |
| 随便练练脑子 | ⑦ 脑力训练周计划 |
| 先随便看看 → | 不选课程，首页显示「从这 3 个开始」（①②③） |

> **"先随便看看"必须保留**，不能强制。选择目标后先展示课程简介与第一步，由用户确认开始；不要在用户仅选择目标后自动打开敏感测评。每个课程必须区分"第一步耗时"与"全程耗时"，避免用户因总时长预期不符而退出。

### 3.2 用户状态与课程选择规则

| 用户状态 | 首屏优先级 | 推荐行为 |
| --- | --- | --- |
| 首次访问、未选目标 | 轻量目标卡 +「先随便看看」 | 目标卡不遮挡页面，不强制弹窗；选目标后先看课程说明 |
| 已选目标、尚未开始 | 目标课程 +「开始第一步」 | 明示第一步内容、耗时、是否为自评问卷 |
| 已开始课程 | 「继续上次」为唯一主行动 | 保留退出、换课和浏览全部入口，不用连续天数制造压力 |
| 从未选目标的回访用户 | 「从上次浏览继续」+ 可选目标卡 | 不反复打断；目标卡可关闭并从首页重新打开 |
| 有明确单项需求的用户 | 搜索 / 浏览全部仍可直接访问 | 课程推荐不拦截直达量表、方法或游戏 |

课程推荐只依据用户主动选择及其本地行为，不根据量表分数推断身份或自动贴标签。用户改目标后只调整推荐顺序，不清除原课程进度。

### 3.3 课程目录（步骤全部引用已存在的 id，已逐一校验）

| 课程 | 适合谁 | 步骤（现有内容 id） | 耗时 |
| --- | --- | --- | --- |
| ① 20 分钟认识自己 | 新用户 / 泛自我探索 | `gses` → `mind6` → 可选路线回顾 | ~20 分钟 |
| ② 职业定位 3 步 | 学生 / 转行 | `holland` → `disc` → `map` → `swot` → `smart` | ~25 分钟 |
| ③ 7 天专注力 | 拖延 / 易分心 | `schulte` → `n-back` → `pomodoro` → `cps` → `flow` | 7 天 × 10 分钟 |
| ④ 7 天情绪调节练习 | 想练习应对压力与情绪 | `box-breathing` → `abc` → `threegood` → `mindful` → `gad7`（可选） | 7 天 × 5 分钟 |
| ⑤ 睡眠与放松 7 天 | 睡不好 | `psqi` → `breath-478` → `mindful` | 7 天 × 5 分钟 |
| ⑥ 关系沟通练习 | 社交困扰 | `ucla` → `nvc` → `johari` | ~15 分钟 |
| ⑦ 脑力训练周计划 | 想练脑 / 提效率 | 注意力 2（`schulte` `cancellation`）+ 记忆 2（`memory-match` `n-back`）+ 反应 2（`whack` `reaction-time`） | 7 天 × 15 分钟 |
| ⑧ 职场减压（二期可选） | 职场人 / 高压 | `pss` → `phq9` → `eisenhower` → `abc` → `mindful` | ~20 分钟 |

> ⚠️ **id 校验说明**：上表 34 个 id 已逐一在三个注册表中核实存在。早期讨论中"睡眠卫生方法"**不存在对应 id**，⑤ 的第 3 步已映射到现有 `mindful`；若确要新增睡眠卫生方法，属内容任务，不在本规划范围。课程标题、每步耗时与总耗时必须在试点前用实际流程复核；表中耗时目前是规划估算。

**每门课程**：`name / tagline / persona / objective / steps[{kind, id, why, task, est}] / outcome`。路线步骤需交代学习意图与本步尝试；结尾提供可选的本地回顾，让用户形成小行动或练习选择。时间标注是路线估时，不等同于训练或练习本身的时长。

**首期实施范围**：已落地自我探索、专注练习、压力调节 3 条路线；现有内容后增加了路线目标、本步尝试提示和可选的实践回顾。回顾不阻挡必做进度，最多记录 500 字，并与路线进度一同保存在本机；用户可清除单条路线进度。自我探索约 20 分钟、专注练习约 30 分钟、压力调节约 28 分钟（均含选做步骤）。表内其余候选路线不在本期上线范围，实际扩展前仍需校验内容、时长与安全文案。

**课程承诺边界**：课程提供的是练习路径，不承诺改善症状、提升分数或达到特定效果。名称避免“急救”“修复”等可能被理解为治疗或快速见效的承诺；“7 天”表示建议节奏，不表示每天必须完成，也不因中断而清零。

多步课程需标明每一步推荐在哪一天完成、是否有休息日，避免“7 天”与实际步骤数量产生矛盾。用户可以按自身节奏继续。

## 4. 交互设计（按场景）

### 4.1 首次进入：只问一个问题（15 秒，可跳过）

首页内的**轻量目标卡**，不做好几页问卷；默认不使用遮挡主页面的强制弹窗：

> **你现在最想解决什么？**
> 🧭 想更了解自己 · 😮‍💨 想调节压力或情绪 · 🎯 想提升专注
> 其他方向 ›
> 先随便看看 →

「其他方向」展开职业、睡眠、人际关系、脑力训练等选项；不要一开始把所有课程都平铺出来。首屏展示哪几个目标先作为试点假设，需通过可用性走查确认，而不是默认这些目标一定最常见。

- 存 `ma_user_goal` + `ma_onboarding_done`；之后只调整推荐排序，完整列表仍可直接访问。
- 选择后先展示对应课程的适合人群、第一步、耗时和退出方式；用户点击「开始」后再进入内容。
- 可随时在首页改目标或清除目标；课程详情提供清除该路线进度的入口，不删除测评、练习或训练记录。
- 目标未选择、目标数据无效或本地数据被清理时，回退到中性首页，不报错、不强制补答。

### 4.2 首页减负（P0，收益最快）

首屏只保留三块，按顺序：

1. **状态卡**：有课程进度时显示「继续上次」和下一步；新用户显示目标引导或「从这 3 个开始」
2. **三个大入口**：测一测 / 学一学 / 练一练
3. **更多**（热门/最近折叠，默认收起）

具体动作：

- 统计数字 27/24/36 从首屏下移或删除——数字强化"目录感"。
- 热门 10 张 → **3 张 + 「换一批」**。
- 搜索从整条输入框收成**右上角图标**，点开再展开。
- 新用户首页 ≠ 老用户首页：新用户「从这 3 个开始」，老用户在状态卡中看到「继续上次」和下一步说明。
- 首页只保留一个承载继续/开始动作的状态卡，避免「继续卡」与单独的「今日一步」重复。主行动优先级固定为：未完成的当前课程步骤 → 未完成的测评/练习 → 目标推荐；三个大入口与「更多」作为次级操作。
- 不显示“今日必须完成”等暗示每日义务的文案；用户中断后继续原进度，不补签、不惩罚。

**可选但有争议（P3 单独评估）**：5 Tab 合并为 4 Tab（"测评/方法"并成"探索"，内部分段）。收益大但影响所有入口与图标资源，**不进 P0–P2**。

### 4.3 列表页：分层展开

- 默认只显示 **「新人首选 4 个」+「为你推荐 3 个」+「查看全部 N 个 ›」**，全库折叠。
- 卡片显示耗时；**耗时筛选**（`≤5 分钟 / 10–20 分钟 / 30+ 分钟`）作为试点后的增强项，确认用户确实需要再纳入，避免首版筛选器过多。
- 卡片减负：去掉「免费」标签（本来就全免费）、描述限一行、题数+时长保留。
- 空态和搜索无结果时给「**先做入门课程**」兜底（指向课程 ①），而不是只显示"没有找到"。
- 搜索结果不受目标排序影响；筛选、搜索与「查看全部」状态应可清晰重置，避免用户误以为内容被隐藏或删除。

### 4.4 详情页：决策优先

首屏先回答 4 个问题，资料往下放：

> 适合谁 → 能知道什么 → 要多久 → 做完能得到什么

- 主按钮文案从「开始测评」改成「**开始（约 X 分钟）**」，时长根据具体内容显示。
- 加「**先看示例结果**」，降低未知感。
- 关联的方法/训练移到**结果之后**推荐（见 4.5），别在开始前再给 10 个选项。

### 4.5 课程详情 + 结果页闭环

- 课程详情 = **时间线**：区分已完成✓ / 进行中▶ / 未开始 / 已跳过，**可随时换课程**（进度保留）。
- 课程页同时展示全程耗时、每步耗时、建议节奏和预计完成条件；允许跳过非必要步骤，跳过与完成分开标识。
- 「继续」返回课程步骤所在内容；完成内容后提供返回课程的明确入口，避免用户做完后找不到路线。
- **结果页底部只留一个主行动**：「根据这个结果，为你安排 3 步」——用现成 `utils/relations.js`（量表类型/显式 id → 相关方法与训练）+ 用户目标生成 top 3，闭环成本最低、价值最高。可一键存为"临时路线"（写入 `ma_course_progress` 的 `adhoc` 条目）。
- 结果推荐需注明“为何推荐”，提供「不感兴趣 / 浏览全部」出口；量表分数不能直接触发诊断性文案、危机判断或强制课程。

### 4.6 个性化机制（规则式，无 ML）

信号按强度排序，全部本地可解释：

1. **用户自述目标（主信号）**：`ma_user_goal`，决定课程大厅排序、列表重排、"为你推荐"。
2. **最近行为（次信号）**：最近 7 天动过什么（`ma_history` / `ma_practices` / `ma_train_*` 均已有）→ 驱动"继续上次"与"接下来推荐"。
3. **档案年龄（弱信号）**：profile 已有生日字段，仅微调课程文案/排序（如 18~24 岁职业课排前），**不做无感知推断**。

> 诚实定位：这是**轻个性化**（目标自述 + 行为），不是 ML 推荐；无后端下这是合理上限。

- 同一内容可能出现在多门课程中；推荐排序需去重，且不得把“展示过/点开过”计为完成。

## 5. 数据与技术落点（守无后端约束）

### 5.1 新增静态配置

`utils/courses-data.js`（新文件）：课程纯数据，结构见 3.3 末尾。复用三个 registry 解析 id，模式同首页 `HOT_CONFIG`。

### 5.2 存储键（全部加进 `utils/storage-keys.js`，保持集中定义、向后兼容）

```js
USER_GOAL: 'ma_user_goal',        // 首启选择的目标（career/emotion/focus/self/sleep/relate/train/browse）
ONBOARDING: 'ma_onboarding_done', // bool
COURSE_PROGRESS: 'ma_course_progress', // { [courseId]: { currentStepId, completedStepIds, skippedStepIds, reflections, startedAt, updatedAt } }
```

**实施决策——路线进度与活动记录分工**：

- `ma_course_progress` 保存路线状态和用户主动填写的可选课程回顾，不复制测评分数、练习内容或训练成绩；不从用户开始课程前的历史记录回填完成状态。
- 回顾仅接受用户主动填写的文字，最多 500 字；不填写也不阻挡必做步骤完成，清除路线进度会一并删除回顾。
- 仅在测评结果成功保存、方法练习成功打卡或训练成绩成功保存后，才将对应步骤记为完成；开始、退出、答题中断或仅查看内容不等同于完成。
- `currentStepId` 指向当前待办步骤；`completedStepIds` 与 `skippedStepIds` 分别记录已完成和已跳过步骤。课程完成度只按必做步骤计算，跳过可选步骤不阻挡完成。
- 用户可在课程详情清除单条路线的状态；仅删除 `ma_course_progress` 中对应课程键值，保留实际活动记录。
- 每次读取进度时仅展示仍存在于课程配置中的步骤状态；课程内容引用由 `npm run validate` 检查。

### 5.3 新增页面

`pages/course/list`（课程大厅，首页"更多"内也复用）+ `pages/course/detail`（时间线）。复用现有 `wx.navigateTo` 跳转与主题封装，**不改答题/训练/练习逻辑**。页面 14 → 16。

### 5.4 一致性闸门

`validate` 新增一条：**课程引用的所有内容 id 必须在对应注册表中可解析**（沿用玩家页一致性闸门思路）。这正是拦截"睡眠卫生方法"这类漂移的机制。

### 5.5 纪律

- 本地 Storage，按现有方式补 Jest；冒烟与 Jest 全套保持全绿。
- `utils/modules-meta.js`、`pages/train/game.json`、`games-block.wxml` 等**生成文件不手改**，数量仍从注册表派生。
- 无障碍沿用现状：交互元素带 `role` / `aria-label`。
- 首启引导、课程卡片和筛选需支持读屏语义、足够触控面积、清晰焦点与不依赖颜色的状态区分；减少动画并尊重系统减少动态效果设置。
- 敏感目标和课程进度属于用户个人信息：只存本地；在隐私说明中说明用途、提供清除入口，不加入埋点、网络上报或未经同意的画像。

## 6. 分阶段落地路线

| 阶段 | 内容 | 涉及文件 |
| --- | --- | --- |
| **准备阶段** | 核对课程 id、记录结构、内容耗时与风险文案；用低保真原型走查首启、继续、退出、搜索和空态 | 规划/原型；不要求先新增页面 |
| **P0** | 首页首屏减负、新老用户分状态；列表页分层展示与卡片减负。保留现有导航与搜索，不与课程系统绑定 | `pages/index/*`、`pages/assess\|methods\|train/*` |
| **P1** | 首启目标卡 + 首批 3 门课程、课程详情时间线、首页继续/目标状态卡、进度纯函数 + Jest、validate 闸门 | 新增 `utils/courses-data.js`、`pages/course/*`；改 `app.json`、`pages/index/*`、`scripts/check-*.js` |
| **试点评估** | 经用户同意后做任务式可用性测试，验证完成首步、继续课程、退出/换课和浏览全部；不采集真实测评答案；修正文案、耗时与流程阻塞 | 研究记录/问题清单 |
| **P2** | 结果页「为你安排 3 步」（复用 `relations.js`）、规则式排序、剩余课程逐门上线 | `pages/result/*`、新增 `utils/recommend.js`、`pages/course/detail` |
| **P3（打磨/待评估）** | 课程完成小结（复用现有存图）+ 完成徽章；5→4 Tab 合并**单独出小方案评估** | 视评估结果 |

工期先视为粗略估算，完成准备阶段后再按确认的首发范围评估。每个开发阶段完成即回归：`npm run validate` + 冒烟 + Jest + `lint:strict` 全绿（CI 同款）。

## 7. 验收标准（可度量）

- 首页主行动 **≤ 1 个**，可见次级入口控制在 4 个以内；“更多”展开后不计入首屏。
- 新用户 **30 秒内**能开始第一个动作（从打开小程序到进入第 1 步内容）。
- 列表页默认首屏 **≤ 8 项**。
- 首步耗时与课程总耗时分别标示；测试用户能在开始前复述自己将做什么及如何退出。
- 测试用户能独立完成「选择目标 → 开始第一步 → 返回课程 → 继续/退出」；记录完成率、耗时和误解点，不以页面点击量替代任务成功。
- 未选目标、搜索无结果、清除本地数据、无可继续步骤时均有可理解的中性空态。
- 课程 id 解析校验 **100%** 通过（validate 闸门）。
- 新增进度状态、目标推荐与页面交互均有 Jest 覆盖，质量门全绿。
- 老用户路径不回归：三个库页"浏览全部"、搜索、历史记录全部可用。

---

## 8. 边界（明确不做的事）

- 不建后端、不强制登录、不做账号/云同步（与离线优先口径一致）。
- 不新造内容：课程**只引用**现有 id；"睡眠卫生方法"等缺口不在本期。
- 不做 ML 推荐；规则式 + 用户自述足够且可解释。
- 不做打卡/连击惩罚、不做推送召回（能力不存在，不造假）。
- 不动生成文件，不改量表/方法/游戏的既有逻辑。
- 不把目标选择、课程参与或量表分数用于诊断、疗效承诺、用户分层标签或网络分析。

## 9. 实施决策与后续事项

1. **课程数量**：首期已上线 3 条试点路线；扩展其他候选路线前先走查闭环与实际耗时。
2. **步骤解锁**：允许自由查看/开始步骤，不锁内容；跳过与完成分别记录。
3. **Onboarding**：采用首页内轻量卡片，不弹窗；已选目标后可在首页更改或清除。
4. **课程完成**：必做步骤全部完成即完成路线；可选步骤不阻挡完成，并在进度中单独标注。
5. **历史记录**：不把开始课程前的旧记录回填为路线完成状态；仅记录课程内成功保存的步骤。
6. **情绪内容安全**：试点仅提供非诊断性自我观察和一般练习，允许跳过/退出；扩展包含高风险题目的课程前，须完成专业与风险文案审查及求助路径核验。
7. **后续决策**：是否增加睡眠/关系/脑力等路线、是否在「我的」中增加目标管理，以及 Tab 5→4 是否合并，均留待试点可用性走查后评估。

## 10. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 课程配置随内容增删发生 id 漂移 | validate 闸门硬校验；课程步骤只允许引用注册表 id |
| 个性化信号弱（无后端、无账号） | 诚实定位为轻个性化；自述目标 + 本地行为已是最强可用信号 |
| 首启引导造成流失 | ≤1 个问题、首页轻量卡片、可关闭、"先随便看看"常驻 |
| 首页改版影响老用户肌肉记忆 | 三个大入口 + "浏览全部"兜底；P0 只减信息不删能力 |
| 首页下一步在无课程时为空 | 空态兜底：按 `ma_user_goal` 推荐对应课程第 1 步；无目标时给通用入门内容 |
| 旧记录让新课程显示已完成，或因数据结构不一漏算完成 | 不从旧活动记录回填；路线状态独立保存，并提供单条课程进度清除入口 |
| 用户把量表或课程理解成诊断/治疗，情绪内容引发不适 | 改用非治疗性名称与描述；结果页再次说明边界；允许立即退出，并给出联系可信赖的人及寻求当地专业/紧急帮助的通用指引 |
| 情绪量表涉及高风险题目，但产品没有危机干预能力 | 相关测评进入课程前做专业审查；不自动解释为诊断或做风险分级；提供可验证、适用于用户所在地的求助信息，无法核验时不写具体联系方式 |
| “7 天”被理解为每日打卡义务 | 明示为建议节奏；不惩罚中断、不清零进度、不制造连续天数压力 |
| 目标或课程进度被误认为云端同步/对外可见 | 清楚说明仅保存在本机；提供清除入口；不添加网络上报 |
| 只看代码验收，实际用户仍不知道下一步 | P0/P1 后做小规模任务式可用性走查；按失败点迭代后再扩课 |
