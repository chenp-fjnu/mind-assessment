# 心智探索局 · 用户交互与「课程」信息架构规划

> **日期**：2026-11-18
> **状态**：规划稿（未动代码）
> **基线**：27 测评 / 24 方法 / 36 训练 / 14 页面 / 纯本地 Storage / 无后端
> **配套文档**：[`ARCHITECTURE.md`](ARCHITECTURE.md)（架构）、[`CODE_REVIEW.md`](CODE_REVIEW.md)（缺陷清单）

---

## 1. 问题诊断

**结论：问题不在于内容多，而在于用户一进来就要自己做「选题」决策。**

87 个内容项（27 测评 + 24 方法 + 36 训练）全部平铺成目录；首页又同时给出统计数字、全局搜索、10 张热门卡、6 张最近卡——用户看到的是**「库」，不是「下一步该做什么」**。

| 位置 | 现状 | 问题 |
| --- | --- | --- |
| 首页 | 数字统计 + 全局搜索 + 10 热门 + 6 最近 | 首屏没有唯一主行动；10 张卡等于"再选一次" |
| 5 个 Tab | 首页/测评/方法/训练/我的 | 三个平行大目录，用户不知道先点哪个 |
| 列表页 | 27 / 24 / 36 项默认全量展开 | 一次扫 20+ 张卡，没有"新人先看这几个" |
| 详情页 | 简介→详解→来源→统计→提示→关联→按钮 | 决策信息（适不适合我、要多久）被资料信息淹没 |
| 新老用户 | 同一套首页 | 新用户没有引导，老用户没有"继续" |

四个结构性缺失：**无个性化**（所有人同一面墙）、**无引导路径**（没有下一步/进度/完成感）、**无叙事**（按学科分类组织，而非按用户目标组织）、**首屏过载**（统计数字强化"目录感"）。

---

## 2. 总体设计：三层信息架构

```
目标（用户自述，1 个问题）
   └─ 课程（3~7 步路线，每步 = 一个现有内容 + 一句"为什么"）
        └─ 全库（现有三个库页，降级为"浏览全部"二级入口）
```

**设计原则**

1. 不加内容，只重组现有内容。课程章节**只引用**现有 id，不复制、不改写任何量表/方法/游戏。
2. 从"内容库"转向"学习路径"：首页主入口从"87 个条目"变成"课程 + 继续上次"。
3. 守住离线优先：无后端、无强制登录、无推送。所有个性化用**规则式**（用户自述目标为主信号），不做 ML。
4. 不做连续打卡惩罚——没有后端和订阅消息，做不到推送，唯一召回手段是"上次停在哪"。
5. 三个库页保留，降级为"浏览全部"，老用户习惯不受损。

## 3. 用户分群 × 课程目录（首批 7 + 1）

### 3.1 首启目标 → 课程映射

| 首启选项（"你现在最想解决什么？"） | 对应课程 |
| --- | --- |
| 🧭 想更了解自己 | ① 3 分钟认识自己 |
| 😮‍💨 情绪/压力有点顶不住 | ④ 7 天情绪急救（职场人可选 ⑧） |
| 🎯 专注力差、总拖延 | ③ 7 天专注力 |
| 🧑‍🎓 专业/职业方向迷茫 | ② 职业定位 3 步 |
| 😴 睡不好 | ⑤ 睡眠修复 7 天 |
| 🫂 人际关系/沟通 | ⑥ 关系沟通练习 |
| 随便练练脑子 | ⑦ 脑力训练周计划 |
| 先随便看看 → | 不选课程，首页显示「从这 3 个开始」（①②③） |

> **"随便看看"必须保留**，不能强制。选择后直接给**一个 3~10 分钟能完成的动作**（课程第 1 步），而不是回首页。

### 3.2 课程目录（步骤全部引用已存在的 id，已逐一校验）

| 课程 | 适合谁 | 步骤（现有内容 id） | 耗时 |
| --- | --- | --- | --- |
| ① 3 分钟认识自己 | 新用户 / 泛自我探索 | `mind6` → `gses` → 结果解读 | ~5 分钟 |
| ② 职业定位 3 步 | 学生 / 转行 | `holland` → `disc` → `map` → `swot` → `smart` | ~25 分钟 |
| ③ 7 天专注力 | 拖延 / 易分心 | `schulte` → `n-back` → `pomodoro` → `cps` → `flow` | 7 天 × 10 分钟 |
| ④ 7 天情绪急救 | 焦虑 / 内耗 | `gad7` → `box-breathing` → `abc` → `threegood` → `mindful` | 7 天 × 5 分钟 |
| ⑤ 睡眠修复 7 天 | 睡不好 | `psqi` → `breath-478` → `mindful` | 7 天 × 5 分钟 |
| ⑥ 关系沟通练习 | 社交困扰 | `ucla` → `nvc` → `johari` | ~15 分钟 |
| ⑦ 脑力训练周计划 | 想练脑 / 提效率 | 注意力 2（`schulte` `cancellation`）+ 记忆 2（`memory-match` `n-back`）+ 反应 2（`whack` `reaction-time`） | 7 天 × 15 分钟 |

**每门课程**：`name / tagline / persona / why / steps[{kind, id, why, est}] / outcome`。完成寄语示例：② 结尾输出"你的兴趣类型 + 一个 SMART 职业目标"；情绪类课程结尾**强制带免责声明**（沿用 about 页口径）。

## 4. 交互设计（按场景）

### 4.1 首次进入：只问一个问题（15 秒，可跳过）

底部**半屏卡片**，不做好几页问卷：

> **你现在最想解决什么？**
> 🧭 想更了解自己 · 😮‍💨 情绪/压力有点顶不住 · 🎯 专注力差、总拖延
> 🧑‍🎓 专业/职业方向迷茫 · 😴 睡不好 · 🫂 人际关系/沟通
> 先随便看看 →

- 存 `ma_user_goal` + `ma_onboarding_done`；之后**所有列表按目标重排**。
- 选完直接进对应课程第 1 步（3~10 分钟可完成），**不回首页**。

### 4.2 首页减负（P0，收益最快）

首屏只保留四块，按顺序：

1. **继续卡**（有课程进度/未完成测评时）或 **目标卡**（新用户首启引导）
2. **三个大入口**：测一测 / 学方法 / 练一练
3. **今日一步**（1 张卡）：`第 2/5 步 · 箱式呼吸 · 约 3 分钟`，一个按钮「继续」
4. **更多**（热门/最近折叠，默认收起）

具体动作：

- 统计数字 27/24/36 从首屏下移或删除——数字强化"目录感"。
- 热门 10 张 → **3 张 + 「换一批」**。
- 搜索从整条输入框收成**右上角图标**，点开再展开。
- 新用户首页 ≠ 老用户首页：新用户「从这 3 个开始」，老用户「继续上次 + 推荐下一步」。

**可选但有争议（P3 单独评估）**：5 Tab 合并为 4 Tab（"测评/方法"并成"探索"，内部分段）。收益大但影响所有入口与图标资源，**不进 P0–P2**。

### 4.3 列表页：分层展开

- 默认只显示 **「新人首选 4 个」+「为你推荐 3 个」+「查看全部 N 个 ›」**，全库折叠。
- 加**耗时筛选**：`≤5 分钟 / 10–20 分钟 / 30+ 分钟`——比按学科分类更贴合"我现在有多少耐心"。
- 卡片减负：去掉「免费」标签（本来就全免费）、描述限一行、题数+时长保留。
- 空态和搜索无结果时给「**先做 3 分钟入门**」兜底（指向课程 ①），而不是只显示"没有找到"。

### 4.4 详情页：决策优先

首屏先回答 4 个问题，资料往下放：

> 适合谁 → 能知道什么 → 要多久 → 做完能得到什么

- 主按钮文案从「开始测评」改成「**开始（约 5 分钟）**」。
- 加「**先看示例结果**」，降低未知感。
- 关联的方法/训练移到**结果之后**推荐（见 4.5），别在开始前再给 10 个选项。

### 4.5 课程详情 + 结果页闭环

- 课程详情 = **时间线**：步骤三态（已完成✓ / 进行中▶ / 未开始），完成打勾，**可随时换课程**（进度保留）。
- **结果页底部只留一个主行动**：「根据这个结果，为你安排 3 步」——用现成 `utils/relations.js`（量表类型/显式 id → 相关方法与训练）+ 用户目标生成 top 3，闭环成本最低、价值最高。可一键存为"临时路线"（写入 `ma_course_progress` 的 `adhoc` 条目）。

### 4.6 个性化机制（规则式，无 ML）

信号按强度排序，全部本地可解释：

1. **用户自述目标（主信号）**：`ma_user_goal`，决定课程大厅排序、列表重排、"为你推荐"。
2. **最近行为（次信号）**：最近 7 天动过什么（`ma_history` / `ma_practices` / `ma_train_*` 均已有）→ 驱动"继续上次"与"接下来推荐"。
3. **档案年龄（弱信号）**：profile 已有生日字段，仅微调课程文案/排序（如 18~24 岁职业课排前），**不做无感知推断**。

> 诚实定位：这是**轻个性化**（目标自述 + 行为），不是 ML 推荐；无后端下这是合理上限。

## 5. 数据与技术落点（守无后端约束）

### 5.1 新增静态配置

`utils/courses-data.js`（新文件）：课程纯数据，结构见 3.2 末尾。复用三个 registry 解析 id，模式同首页 `HOT_CONFIG`。

### 5.2 存储键（全部加进 `utils/storage-keys.js`，保持集中定义、向后兼容）

```js
USER_GOAL: 'ma_user_goal',        // 首启选择的目标（career/emotion/focus/self/sleep/relate/train/browse）
ONBOARDING: 'ma_onboarding_done', // bool
COURSE_PROGRESS: 'ma_course_progress', // { [courseId]: { stepIndex, startedAt, updatedAt } }
```

**关键决策——进度双轨**：

- `ma_course_progress` 只存**路线状态**（哪门课、走到第几步），不存"是否完成"。
- 每步**完成与否从现有记录派生**，不重复记账：
  - 测评步 → `ma_history` 有该 id 记录（或 `ma_progress_<id>` 续答中）
  - 方法步 → `ma_practices[id]` 有打卡
  - 训练步 → `ma_train_<id>__*` 有成绩
- 好处：零新增记录逻辑；完成状态可信（真做过才算）；换设备清缓存的既有免责口径不变。
- 进度计算写成**纯函数**（输入：课程配置 + 三类记录 → 输出：每步状态/整体进度），直接进 Jest。

### 5.3 新增页面

`pages/course/list`（课程大厅，首页"更多"内也复用）+ `pages/course/detail`（时间线）。复用现有 `wx.navigateTo` 跳转与主题封装，**不改答题/训练/练习逻辑**。页面 14 → 16。

### 5.4 一致性闸门

`validate` 新增一条：**课程引用的所有内容 id 必须在对应注册表中可解析**（沿用玩家页一致性闸门思路）。这正是拦截"睡眠卫生方法"这类漂移的机制。

### 5.5 纪律

- 纯函数 + 本地 Storage，按现有方式补 Jest；冒烟 182 项与 13 个 Jest 套件保持全绿。
- `utils/modules-meta.js`、`pages/train/game.json`、`games-block.wxml` 等**生成文件不手改**，数量仍从注册表派生。
- 无障碍沿用现状：交互元素带 `role` / `aria-label`。

## 7. 验收标准（可度量）

- 首屏可点元素 **≤ 5 个**。
- 新用户 **30 秒内**能开始第一个动作（从打开小程序到进入第 1 步内容）。
- 列表页默认首屏 **≤ 8 项**。
- 课程 id 解析校验 **100%** 通过（validate 闸门）。
- 新增逻辑（进度计算/推荐排序）**纯函数 + Jest 覆盖**，质量门全绿。
- 老用户路径不回归：三个库页"浏览全部"、搜索、历史记录全部可用。

---

## 8. 边界（明确不做的事）

- 不建后端、不强制登录、不做账号/云同步（与离线优先口径一致）。
- 不新造内容：课程**只引用**现有 id；"睡眠卫生方法"等缺口不在本期。
- 不做 ML 推荐；规则式 + 用户自述足够且可解释。
- 不做打卡/连击惩罚、不做推送召回（能力不存在，不造假）。
- 不动生成文件，不改量表/方法/游戏的既有逻辑。

---

## 9. 开放决策点（开工前需拍板）

1. **首批课程数量**：一次做 7 门，还是先做 3 门（①②③，覆盖面最广）验证链路？
2. **步骤解锁方式**：建议**自由跳转 + 进度展示**（自我探索产品做"上锁"体验偏重，且会打断想直接练某个游戏的老用户）。
3. **Onboarding 形态**：建议首页内底部半屏卡（非强制、可跳过、一次可再答），而非独立引导页。
4. **课程"完成"标准**：全部步骤走完，还是"至少 1 测评 + 1 方法"即算完成？（后者更现实）
5. **Tab 5→4 合并**：是否值得？建议 P3 单独评估，不进主线。

## 10. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 课程配置随内容增删发生 id 漂移 | validate 闸门硬校验；课程步骤只允许引用注册表 id |
| 个性化信号弱（无后端、无账号） | 诚实定位为轻个性化；自述目标 + 本地行为已是最强可用信号 |
| 首启引导造成流失 | ≤1 个问题、半屏卡、可跳过、"随便看看"常驻 |
| 首页改版影响老用户肌肉记忆 | 三个大入口 + "浏览全部"兜底；P0 只减信息不删能力 |
| "今日一步"在无课程时为空 | 空态兜底：按 `ma_user_goal` 推荐对应课程第 1 步 |
